03 — THE AGENT

How 100 apps got researched without a hundred humans

A six-stage pipeline. The agent drafts, checks its own work against the live web, and drafts corrections - a human closes the loop. Total runtime on a laptop: minutes, fully re-runnable.

STAGE 1

Pass 1 — the draft agent

LLM drafts all 100 apps from its own knowledge, batched 10/call, no web access. This is the honest starting point: fast, broad, and wrong in instructive ways.

10 Gemini calls · cached to out/llm_cache/
STAGE 2

Verify — live evidence loop

Every evidence URL is fetched: HTTP status, redirects, and page-text sniffing for auth/API keywords. A rule engine adds cross-field contradiction checks.

100 URLs pass 1 · requests + ThreadPool
STAGE 3

Deep-dive — the research agent

Flagged rows get their real docs pages fetched; an LLM extracts facts strictly from that text with verbatim quotes. Output: proposals, never auto-applied.

38 rows flagged → 38 proposals
STAGE 4

Human review — the loop's exit

Proposals are reviewed by a human who promotes corrections into data/overrides.csv. The dataset ships with the promoted ledger; every change is traceable.

911 field corrections promoted
STAGE 5

Pass 2 + independent audit

Overrides are applied, the whole pass is re-verified, and both passes are scored against a hand-built ground truth sample fixed before grading.

audit: 20 apps × 5 fields, strict match
STAGE 6

Patterns + page

Distributions, clusters and the headline insights are computed from the final dataset; this page is generated from the artifacts.

pure python + inline SVG · zero page deps

Where a human was needed - said plainly

  • Conflict resolution. Docs, pricing pages and changelogs sometimes disagree (auth "deprecated but still working", MCP "announced but unreleased"). The agent flagged; the human decided.
  • The unreadable tail. A few apps (Paygent Connect, iPayX, fanbasis) publish no usable public docs at all. The agent said so; the human confirmed it is genuinely a dead end, not a parsing failure.
  • Verdict judgment. "Ready with caveats" is an opinion. The agent proposed; the human owned the final call.
  • Infra reality. The provided Composio API key is rejected by the current v3 API (HTTP 401 - the key predates the migration), so the toolbelt cross-check degrades gracefully instead of guessing.

06 — HONESTY

What this research can and cannot promise

Said plainly

  • The audit is 20 apps, not 100. The sample spans all categories and difficulty levels, but the remaining 80 rows were verified by evidence-link checks and rules, not field-by-field by a human.
  • Pass 2 was built with sight of the sources. The human reviewer and the auditor used the same primary docs - the audit exists to grade the untouched first pass and confirm the loop's corrections, not to claim independent discovery. The number to trust is the delta: 70% → 100%.
  • LLMs are nondeterministic. Re-running pass 1 fresh will produce slightly different drafts (that is why the draft, its cache and all artifacts are committed). Pass 2 is deterministic: it is data + overrides.
  • MCP is a moving target. MCP status was checked against registries and vendor docs in September 2026; vendors ship servers monthly. Treat MCP="No" as "no at research time".
  • Gating is plan-dependent. "Paid self-serve" can change with pricing pages; where a plan changed the answer, gate_detail says how.
  • What defeated us: 3 apps with no public API, and vendor docs that render behind JS logins the evidence checker cannot see past. Those rows carry low confidence rather than invented answers.
  • Verify the verifier: every claim's source is one click away in the matrix; out/research_report.json mirrors this page for agents.
